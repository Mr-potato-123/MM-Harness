# Method Diagramming

Use a method diagram only when structure is materially clearer visually: an overall roadmap, data pipeline, question dependency graph, algorithm branch, model architecture, or indicator hierarchy. Do not redraw numerical results, distributions, sensitivity curves, or comparisons that belong to data visualization.

Derive every node and edge from the accepted modeling report. Keep labels short, direction unambiguous, decision branches explicit, and visual grammar consistent. Avoid crossed edges, decorative depth, dense prose, and diagrams created only to increase figure count.

Store an editable source when a diagram tool is available and export a publication-ready vector artifact. Record purpose, source report, intended section, caption meaning, and export status. Verify that the diagram does not contradict the implemented code or downstream task order.
